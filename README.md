# mark-support-mvp

中小企業向けPマーク取得・運用支援ツールのMVP

最初の業務機能として、教育管理MVPを実装済みです。ブラウザから
「対象者確認 → 不足の把握 → 不足解消操作 → 再評価 → 適合」という
一連の流れをデモできます。

## 構成

* Python 3.12
* FastAPI
* Uvicorn
* Pydantic
* pytest
* GitHub Codespaces / devcontainer

## 起動

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

起動後、ブラウザで `http://localhost:8000/` にアクセスするとトップページが、
`http://localhost:8000/health` にアクセスするとヘルスチェック用のJSONが表示されます。
`http://localhost:8000/education` にアクセスすると教育管理デモ画面が表示されます
（トップページからもリンクしています）。`http://localhost:8000/documents` に
アクセスすると、文書一覧（個人情報管理台帳・教育手順・委託先管理手順）が表示されます。

## テスト

```bash
python3 -m pytest -q
```

## 教育管理MVP デモ

教育管理を題材に、「事実データ → 業務ルール → 評価結果」を分離した構造を
ブラウザ上で確認できます。判定ロジック（`app/education.py` の
`evaluate_training()`）はHTML/APIから独立しており、画面側で独自の適合判定は
行いません。

### デモ企業

`株式会社サンプル`（従業者50名）の固定データを、サーバー起動時にメモリ上へ
構築します。

* 経営者1名、個人情報保護管理者1名、Pマーク担当者1名、一般従業員47名（全員active）
* 教育対象者50名のうち、初期状態では48名が受講済み・2名が未受講
* 受講済み48名のうち3名は理解度確認が未登録
* 教材証跡は未登録、実施結果は未承認

### デモシナリオ

1. `/education` を開くと、会社情報・教育管理策・規程条項プレビュー・
   年間教育計画・教育実績（未受講/要確認者を優先表示）・整合性チェック結果
   が表示されます。
2. 初期状態は **要対応**（`EDU-003` 未受講者2名 / `EDU-006` 理解度確認不足
   3名 / `EDU-008` 教材証跡未登録 / `EDU-009` 未承認）です。
3. 画面下部のボタンで、未受講者の受講済み化・理解度確認登録（`pass`）・
   教材証跡登録・承認、をそれぞれ操作できます。
4. 各操作のたびに `evaluate_training()` が再実行され、結果が画面に反映され
   ます。すべて解消すると **適合** になります。
5. 「デモを初期状態に戻す」ボタンで、いつでも初期状態（要対応）に戻せます。

### データ保存について

DBは使用していません。デモ状態はプロセス内メモリのみで保持しており、
サーバーを再起動すると初期状態（要対応）に戻ります。

## Codespaces

GitHub Codespacesでリポジトリを開くと、`.devcontainer/devcontainer.json` の設定に従って
Python 3.12環境が構築され、`requirements.txt` が自動でインストールされます。
ポート8000がフォワードされるため、起動後はブラウザからそのままアクセスできます。

## 文書生成MVP

setupで確認済みの個人情報・採用済み管理策から、標準テンプレート
（`app/document_templates.py`）に事実データを当てはめて文書（`app/documents.py`）を
組み立てます。AIによる自由作文は行いません。今回生成する文書は次の3種類です。

* 個人情報管理台帳：confirmedな個人情報から一覧を生成（管理策の採用有無は問わない）
* 個人情報保護教育手順：`education` 管理策がadoptedの場合のみ生成
* 委託先管理手順：`vendor_management` 管理策がadoptedの場合のみ生成

各文書は `draft`（下書き・情報不足）／`ready`（準備完了）／`not_applicable`
（管理策未採用のため生成対象外）のいずれかの状態を持ち、不足している情報は
文書プレビュー画面に明示されます。文書はリクエストのたびに元データから組み立て
直すため、setupや教育・委託先管理の画面でデータを変更すると、次に文書を開いた
ときに内容が更新されます（文書のスナップショット保存・版管理は未対応）。

## 現在のMVP方針

教育管理・委託先管理・初期設定（個人情報台帳・リスク・管理策）・文書生成MVPを
実装済みです。DB・認証・AI文章生成・文書の版管理・電子署名などは今回も未導入です。
